## This repo

- **Package id is `open-webui`.** One `ui` interface on port 8080 (the `ui-multi` MultiHost); nothing is exported for dependents.
- **AI backends are optional dependencies wired through the app's own DB, not env overrides.** `startos/backends.ts` is the single source of truth for the compatible backends (Ollama, vLLM, llama.cpp, Maple Proxy) — the Configure Backends action, `setupDependencies`, and `setupMain`'s key re-sync all derive from it. Adding a backend is a one-line addition there.
- **Backends are reached over the local service bridge** (`10.0.3.1:<assigned external port>`), resolved reactively through `sdk.host.getBridgeAddress` — never `<pkg>.startos` overlay DNS. `startos/backends.ts`'s `resolveBaseUrls` builds an `id → base URL` map from each dependency's exported host-id/port consts (imported via the `github:…#next` pins in `package.json`); `main.ts` and `setDependencies` resolve with `.const()` (a backend install/uninstall/port-change heals with one restart, a dep update causes none), the Configure Backends action with `.once()`. The resolved URL doubles as the match key written to `webui.db`, so `deriveView` matches against the freshly resolved address. A backend that lands on a new assigned port is repointed automatically by `repointBackendUrls` in `setupMain`, which rewrites our entry in place (index-preserving, so `openai.api_keys` stays aligned) using the per-backend URL Configure Backends recorded in `store.json`; an uninstalled backend keeps its entry until the user removes it.
- **An env var is a one-shot seed, never an override — so config goes in `webui.db`.** Since Open WebUI 0.10, `Config.seed_defaults` writes every PersistentConfig key into the `config` table on the launch that finds it missing, and the stored row wins from then on whether or not the user ever edited it. `startos/utils.ts`'s `daemonEnv` therefore carries **only** variables Open WebUI re-reads each launch (`WEBUI_SECRET_KEY`, `CORS_ALLOW_ORIGIN`, `WEBUI_SESSION_COOKIE_SECURE`, `ENABLE_VERSION_UPDATE_CHECK`, `ENABLE_ADMIN_ANALYTICS`); adding a PersistentConfig var there would silently do nothing after first launch. Everything else is declared in `startos/managedConfig.ts` as either **seed** (written once at install) or **reconciled** (re-asserted by `setupMain` before the daemon starts, for values whose correct setting can change under the user — a dependency installed later, a bridge port that moves). Reconcile never overwrites a value the user changed: the last value we wrote is recorded in `store.json` and anything else non-empty is left alone.
- **`webui.db` is read/written via a temp `open-webui` SubContainer running `python3`** (`startos/webuiConfig.ts`), in flat dotted keys (`ollama.base_urls`, `web.search.searxng_query_url`); the two physical shapes (per-key rows >= 0.10, one JSON blob before) are handled inside the scripts. `writeConfig` refuses to act when `webui.db` is absent — `sqlite3.connect` would create an empty file that Alembic then inherits, which is the issue-#15 corruption. The Configure Backends action additionally gates on `adminExists`.
- **`isOurs` is one-way, so `reclaimManagedConfig` is the escape hatch.** `reconcileManagedConfig` skips any value the user changed, and the only state that releases a key back (empty) is one Open WebUI's admin form refuses to save — its Searxng Query URL input is `required` upstream, inside a form with native validation. That makes a single hand edit permanent. The **Reconnect SearXNG** action calls `reclaimManagedConfig`, the one caller allowed to bypass `isOurs`, because it only ever runs on an explicit user request. Don't call it from `setupMain` or `init` — that would defeat the ownership rule it exists alongside. It reclaims _every_ `RECONCILED` key while being named for the only one that exists, so a second reconciled key means revisiting the action's name, its guard, and the task condition together.
- **A key with no ownership record at all is a pre-`0.11.0:1` install, and the one case reconcile repairs by itself** (`isStranded` + `aimedAtUs`). Every write path since `0.11.0:1` claims its key, so a missing record can only predate that. Don't widen it to values we _do_ have a record for — that is the ownership rule, not a gap in it. Transitional; `TODO.md` tracks its removal.
- **A declined key raises a task, because failure here is silent.** `setupMain` turns a declined SearXNG key into an `important` `createOwnTask` (`critical` would block startup). StartOS drops a `when`-less task when its action runs, so the paired `clearTask` exists only for the other exits — SearXNG uninstalled, or the value corrected by hand.
- **Install boots the service once, and that is what removes first-run branching everywhere else** (`startos/init/bootstrap.ts`, `runUntilSuccess`). Open WebUI's first launch is the only thing that creates `webui.db` and its schema, so booting it during init lets `setupMain`, the actions, and `seedManagedConfig` all assume the table exists. The same init step first copies the image's baked 265 MB model cache (embedding models, Whisper, tiktoken) onto the volume: it lives at `/app/backend/data/cache` — the only thing in `/app/backend/data` in the image — which `mainMounts` covers, so without the copy every one of those models is re-fetched from HuggingFace on demand. It does not remove that dependency outright: `sentence_transformers` pulls a 30-file snapshot of the embedding repo (more formats than the image bakes) which the bootstrap boot completes, so **install still needs network**; what the copy buys is Whisper and tiktoken, which load lazily and are never covered by that boot. Anything else this package mounts over an image path deserves the same check.

## Inspecting a running install

To run a command inside the service's container (read its generated config, grep app logs), use `start-cli package attach open-webui -n open-webui-sub -- <cmd>`. Select the subcontainer by **name** with `-n` (the name passed to `SubContainer.of` in `main.ts` — here `open-webui-sub`) or by image with `-i`. Note: `-s/--subcontainer` matches the internal **Guid**, not the name, so passing a name to `-s` fails with "no matching subcontainers".
